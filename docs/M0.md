# M0 — Socle

**Objectif.** Une app vide mais déployable de bout en bout : dépôt, base, tests, CI, conteneurs, mise en ligne sur le VPS. Aucune fonctionnalité produit.

**Terminé quand** le kit d'interface issu de la maquette répond en HTTPS sur le VPS, avec sa base Postgres, et que la CI passe.

## Périmètre

Dans cet ordre, un commit par point.

1. **Projet.** Next.js (App Router), TypeScript strict, pnpm, ESLint, Prettier, alias `@/` vers `src/`. Sortie `standalone` pour Docker. Dernières versions stables, Node LTS.
2. **Jetons et styles.** Tailwind CSS. Un script `pnpm tokens` lit `design/tokens.json` et génère `src/app/tokens.css` (variables CSS : couleurs, espacements, rayons). Les couleurs Tailwind pointent sur ces variables. Un seul thème, `nuit`.
3. **Polices.** Bricolage Grotesque (texte) et DM Mono (chiffres) via `next/font/google`, exposées en `--font-display` et `--font-mono`.
4. **Kit d'interface.** Les composants de base de `docs/design.md` dans `src/components/ui` : `Button`, `IconButton`, `Chip`, `Segmented`, `Card`, `MomentBadge`, `Countdown`, `BetOption`, `Amount` et ses trois icônes, `Ticket`, `Stamp`, `Avatar`, `LeagueBadge`, `LeagueSwitcher`, `BottomSheet`, `TabBar`, `TextField`. Une page `/kit` les montre dans tous leurs états, avec des données d'exemple, fidèles à `design/screens`. `/` affiche le nom « JentApp » et un lien vers `/kit`. Aucun écran produit n'est construit dans ce jalon.
5. **Base.** Postgres en conteneur. Drizzle et drizzle-kit, client dans `src/db/client.ts`, scripts `db:generate` et `db:migrate`, migrations appliquées au démarrage du conteneur. Pour valider le pipeline, une seule table : `app_meta (key text primary key, value text)`.
6. **Santé.** `GET /api/health` exécute `select 1` et répond `200 {"status":"ok","db":"ok"}`, ou `503` si la base ne répond pas.
7. **Tests.** Vitest. Un test unitaire, et un test d'intégration qui parle à un vrai Postgres (celui du compose en local, un service en CI). C'est la base des tests d'économie de M2.
8. **Conteneurs.** `Dockerfile` multi-étapes (dépendances, build, exécution en utilisateur non root). `docker-compose.yml` avec `app` et `db`, volume `pgdata`, volume `uploads` monté dans `app`, healthchecks, `app` qui attend `db`. Le port de l'app n'écoute que sur `127.0.0.1`. `.env.example` à jour.
9. **CI.** GitHub Actions sur chaque PR et chaque push sur `main` : installation, lint, typecheck, tests avec Postgres, build. Sur `main`, construction et publication de l'image sur GHCR.
10. **Déploiement.** Dossier `deploy/` : compose de production (image GHCR, `restart: unless-stopped`), exemple de configuration Nginx (proxy vers l'app ; sur `/api/stream`, `proxy_buffering off` et délais longs, en prévision du SSE). Procédure pas à pas dans `docs/DEPLOY.md` : certificat Certbot, premier lancement, mise à jour, lecture des logs.
11. **Dashboard.** Entrée JentApp dans `config/services.yaml` du dashboard Homepage : icône, `siteMonitor`, intégration du conteneur.
12. **PWA minimale.** `manifest.webmanifest` (nom, couleur de fond `bg`, icônes de `design/icon` en `any` et `maskable`), `apple-touch-icon` et favicon. Pas de service worker avant M7.
13. **Docs.** `README.md` court (lancer en local, lancer les tests). `CLAUDE.md`, `docs/spec.md`, `docs/design.md` et `design/` sont déjà dans le dépôt, ainsi que `content/legal`.

## Hors périmètre

Authentification, ligues, toute table métier, SSE, service worker, push, sauvegarde automatisée de la base.

## Critères de fin

- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` et `pnpm build` passent en local et en CI.
- [x] `docker compose up` en local : `/` et `/kit` s'affichent, `/api/health` répond `ok`.
- [x] Sur `/kit`, à 390 px de large, chaque composant est conforme à ce que montrent les pages de `design/screens`.
- [x] Aucune couleur, aucun rayon ni espacement en dur dans `src/components/ui`.
- [ ] L'image est publiée sur GHCR par la CI.
- [x] Aucun secret dans le dépôt.

## Reportés à M7

Ces critères demandent le VPS ; ils se vérifient avec la mise en production de M7.

- [ ] L'app répond en HTTPS sur le domaine retenu, `/api/health` répond `ok`.
- [ ] Après un redémarrage du VPS, l'app et la base repartent seules et les données sont toujours là.
